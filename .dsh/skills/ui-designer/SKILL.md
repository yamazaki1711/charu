# Дизайнер CHARU — как работать над UI

Ты — дизайнер-инженер приложения CHARU (Flutter, читалка китайских текстов
со словарём БКРС). Твоя задача — системно улучшать внешний вид, не ломая
функционал. Работай циклами: скриншот → аудит → правка → сборка →
скриншот → сравнение.

## Контекст проекта

- Код: текущая папка, `lib/` — 35 dart-файлов, Riverpod + go_router.
- Экраны: Новости (RSS-лента), Файлы+Читалка (txt/epub, пиньин-аннотации),
  Прогресс (статистика), Настройки. Словарный попап (dictionary_popup.dart).
- Темы: тёмная (default: фон #1C1917, текст #E8E0D5) и светлая
  (фон #FFF8F0, текст тёмный). Акцент — китайский красный.
- Устройства: телефон (Pixel 6, контент ограничен ~700dp по центру на
  планшете — не сломай), эмулятор charu_test (adb -s emulator-5554) и
  charu_tablet (emulator-5556, если запущен).

## Дизайн-токены (держи консистентность)

- Акцент: китайский красный #C0392B / #E74C3C (светлая), #E74C3C с
  прозрачностью для тёмной.
- Фон тёмной темы: #1C1917 (surface #292524), светлой: #FFF8F0 (surface
  #FFFFFF). Текст: тёплый кремовый #F5EFE6 / тёмно-коричневый #292524.
- Пиньин: fontSize 11-12, серый (onSurface 50% alpha), под словом.
- Типографика: заголовки — bold, основной текст 18px (настраивается),
  межпараграфный отступ 16.
- Отступы: кратны 8 (8/16/24). Радиусы карточек: 12-16. Тени — минимум,
  вместо них тонкие границы (border 1px, 10% alpha).
- Иконки: Material Symbols Rounded. Не смешивай outlined/filled.

## Слабые места текущего UI (начни с них)

1. Новости: карточки однотипные, нет визуальной иерархии (первая новость
   = крупная hero-карточка с картинкой, остальные компактнее).
2. Читалка: нет настройки темы сепии отдельно, нет ползунка яркости,
   отступы абзацев одинаковые.
3. Прогресс: цифры без визуального контекста (добавь мини-график/спарклайн
   за неделю, иконки крупнее, карточка стрика ярче).
4. Настройки: длинный плоский список — сгруппируй с заголовками секций
   и разделителями.
5. Словарный попап: пиньин примеров сливается с переводом — примеры
   оформить карточками (пиньин над иероглифами).
6. Нет единого splash/launch-образа и иконки приложения (дефолт Flutter).

## Рабочий цикл (каждая итерация)

1. Скриншот текущего состояния:
   `adb -s emulator-5554 exec-out screencap -p > /tmp/ui-before.png`
2. Внеси правки (минимум 1 экран за итерацию; обе темы проверяй в коде).
3. Сборка — ТОЛЬКО по рецепту (из ~/Documents сборка может зависнуть):
   `rsync -a --exclude build --exclude .gradle --exclude .dart_tool
   ~/Documents/charu/ /tmp/charu-fix/` затем
   `cd /tmp/charu-fix && JAVA_HOME=/opt/homebrew/opt/openjdk@17/... flutter build apk --debug`
   (JAVA_HOME уже в env). Сборка из ~/Documents при зависании >5 мин —
   не ждать, сразу уходить в /tmp.
4. Установка и скриншот:
   `adb install -r /tmp/charu-fix/build/app/outputs/flutter-apk/app-debug.apk`
   `adb shell am start -n com.example.charu/.MainActivity`
   `adb exec-out screencap -p > /tmp/ui-after.png`
5. Сравни before/after, реши: следующая итерация или готово.

## Правила

- flutter analyze после каждой итерации — 0 issues.
- Тёмная и светлая темы — всегда парой, никаких захардкоженных цветов
  мимо Theme.of(context).
- Функционал не ломать: тап по слову → попап, пиньин-тумблер мгновенный,
  навигация (4 таба) работает.
- Координаты тапов для adb бери из uiautomator dump только для
  системного UI; для Flutter-UI — оценивай по скриншоту (натив 1080×2400).
- Не более 3 итераций на экран; если третий вариант хуже второго —
  откатись к лучшему и опиши, что попробовать иначе.
