# CHARU — правила работы для агента

## Индикация прогресса (важно для пользователя)

Пользователь следит за работой через панель To-dos в интерфейсе. Поэтому:

- **Всегда** создавай to-do список в начале задачи (todo_write) — разбивай
  задачу на шаги, которые занимают не больше ~10 минут каждый.
- **Перед началом каждого шага** переводи его в `in_progress`.
- **Сразу после завершения** — в `completed`. Не копи «готово» на потом.
- Если шаг затянулся (сборка, загрузка) — обнови список, чтобы было видно,
  чем занят: текущий in_progress и есть индикатор «работаю».
- В конце хода: короткий отчёт + все пункты в `completed` (или пометка,
  что осталось).

## Сборка APK

Сборка из ~/Documents может зависнуть после конфигурации (0% CPU > 5 мин).
Рабочий обход: rsync проекта в /tmp/charu-fix (исключая build/.gradle/
.dart_tool), собирать там (JAVA_HOME в env), вернуть APK в
build/app/outputs/flutter-apk/. Пиньин-аннотации, тёмная/светлая темы и
тап-попап словаря — не ломать.


## Мультиагентность (делегирование субагентам)

Доступен инструмент `subagent` (spawn, continuable — ребёнок сохраняет
сессию, до 8 параллельных). Используй Kimi-K-стиль оркестрации:

- Задачу с независимыми подзадачами РАЗБИВАЙ и ДЕЛЕГИРУЙ параллельно
  (несколько вызовов subagent подряд = дети работают одновременно).
- Один вызов subagent = одна самодостаточная подзадача: контекст,
  файлы, критерий результата. Ребёнок не видит твою переписку.
- Типовые роли: аудит-воркер (прочитать N файлов, вернуть находки),
  тест-воркер (прогнать тесты, вернуть упавшие), исследователь
  (собрать факты по вопросу).
- Результаты агрегируй сам; ребёнок возвращает только итоговый текст.
- Не делегируй то, что делается одной правкой. Не ставь больше 4
  детей на одну задачу (GPU один — модель делит между ними).
